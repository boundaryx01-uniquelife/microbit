# 새 교구 접수 체크리스트

교사·제조사에게 받거나 직접 조사한다. 표로 채우고, 못 채운 칸은 "확인 필요"로 둔다(나중에 문서의 '미검증'으로 이어짐).

| # | 항목 | 왜 필요한가 |
|---|---|---|
| 1 | 제품명·한글 표기·제조사, 상표·로고 사용 허락, 확장 라이선스, "협력/비공식" 표기. **기존 교구 제조사와의 협력 표기·그 회사 교안에서 파생된 문장은 새 사이트로 그대로 가져가지 않는다**(재작성 또는 허락) | 사이트 문구·NOTICE·로고, 저작권 |
| 2 | MakeCode 확장 GitHub 주소·버전(유선/무선 분리 여부), 전체 블록 목록(한글 블록명 ↔ JS 호출 ↔ 인자 범위·enum) | 예제·시뮬레이터 API·도우미 프롬프트의 원천 |
| 3 | 마이크로비트 장착 방식(v1/v2, 꽂으면 A·B 버튼이 가려지는지), 본체 버튼 | 입력 방법이 수업 흐름을 바꿈(가려지면 본체 버튼·라디오) |
| 4 | 통신·핀: 확장이 시리얼·특정 핀을 쓰는지(USB 시리얼 충돌), 라디오 그룹·밴드 | 브리지 수신기에 확장을 넣으면 안 되는 경우 |
| 5 | 구동: 바퀴/다리 수, 서보·모터, 관절 범위, 치수, 값 범위(속도 0~?, 각도 등)와 실측(최대 속도에서 cm/s, 회전 °/s — 없으면 추정으로 표시) | 시뮬레이터가 실제처럼 움직이게(안전 한도는 교사가 정함) |
| 6 | 입출력: LED(종류·해상도·위치), 소리, 거리/라인/색 센서(값 범위·오류값), 배터리, 카메라 | 장치 감지·시험·도우미 어휘 |
| 7 | 수업 환경: 책상 위/바닥, 추락·충돌 대비(정책 값은 교사가 정함) | 수업 안내·시뮬레이터 추락 표시 |
| 8 | 수업: 학년·차시·시수, 목표, 기존 교안·활동지, AI로 알아볼 대상(카드·색·물건) | 2·4·8차시 구성 |
| 9 | 자산: 제품 사진(정면·측면·위), CAD/3D·공식 시뮬레이터, 영상, 매뉴얼, 브랜드 색 | 마스코트·아이콘·3D 모형 |
| 10 | 배포: 도메인·Netlify, 도우미 AI 사용 여부·예산(모델·키), 학교망 허용 주소 | 운영 |
| 11 | 검증: 실물 확보 여부, 실측 가능 항목(관절 표본, 센서값) | '미검증' 범위 |
