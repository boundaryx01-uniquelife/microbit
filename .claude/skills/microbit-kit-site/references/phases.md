# 단계별 상세

## 3. 틀 준비
- 새 저장소로 복사(또는 `kit/<slug>` 브랜치). 사이트 루트 `bridge/`, 함수 `netlify/functions/`, 생성기 `tools/`, 시험 `tests/`.
- 교구 종속 값 모으기(`inventory.md` 3절의 `kit/`): 먼저 **읽기 전용 목록화를 하위 에이전트(Sonnet)**에 맡겨 "파일:줄 → kit/ 어느 키"를 만들고, 메인이 이동 순서를 정한다. 같은 파일 수정은 메인 한 곳에서.
- 옛 교구 이름 grep으로 남은 곳 확인(생성물 `bridge/docs/*.html`, `sim/examples.js`는 원본을 고치고 다시 생성).

## 4. 교구 어댑터
1. **블록 표(api.json)**: 확장 소스(GitHub `main.ts`/`pxt.json`)에서 블록 이름·JS 이름·인자·enum을 추출. 한글 블록명은 MakeCode 한국어 화면 기준.
2. **예제 `.ts`**: 기존 예제 흐름(00 수신기 → 01 인사 → 02 거리 규칙 → 03 AI 신호등 → 04 모둠 템플릿 → 버튼/리모컨 예제)을 교구 블록으로. 각 예제 머리 주석에 필요한 확장·장치. `tests/makecode-blocks.js`로 실제 MakeCode에서 블록 변환 확인(확장 추가 → 붙여넣기 → 블록).
3. **시뮬레이터**: `makeRobodogApi` 같은 API 객체를 api.json 구동 어댑터로, 추정 상수(EST)와 표정·LED 비트맵, 장치 감지 정규식(`devices.js`).
4. **도우미**: 규칙 엔진(문장 → 코드 템플릿, 안전 클램프)과 서버 프롬프트(블록 문법 발췌 + 안전 규칙)를 같은 safety 값으로. 못 하는 요청은 알맞은 예제로 안내.
5. **시험**: 교구 수치가 들어간 시험(sim-e2e 거리·회전, rule-assistant 한도, sim-examples) 갱신. 시험 항목 수는 README에 실제 값으로.

## 5. 수업 자료
- 수업 판: 2차시 소개형(체험), 4차시 기본형(AI 가르치기 + 규칙), 8차시 전체형(문제 해결 프로젝트). 교구 특성에 맞는 이야기(예: 신호등 멈춤, 길 안내, 배달) 하나를 골라 2·4·8차시를 관통.
- 슬라이드 JSON(스키마 `bridge/lessons/SCHEMA.md`) → PPT. 활동지·평가·운영 가이드(학교 PC 점검표, 학교망 주소, 안전장치, 문제 해결) md.
- 화면 캡처(시뮬레이터·브리지)는 바뀐 화면으로 다시.
- 사용자 관점 리뷰(학생·교사)를 하위 에이전트(Sonnet)로 — 용어 통일(예: "모둠 번호", "본체 버튼"), 교실 거리 가독성.

## 7. 점검·배포 메모
- 실물 미검증 항목을 검증 보고서 '미검증' 절과 교사 실기 점검표로.
- 첫 배포 뒤 학교 PC·휴대폰에서 첫 화면·브리지(Web Serial)·시뮬레이터 확인을 사용자에게 요청.
