# 마이크로비트 교구 사이트 만들기

기준 구현: `boundaryx01-uniquelife/microbit`(빅아이 로보독 × 마이크로비트, https://microbit-bridge.netlify.app). 새 교구는 **이 틀을 복사해 교구 종속 부분만 바꾼다** — 처음부터 만들지 않는다.

## 이 스킬이 다루는 범위
| 다시 씀(교구 무관) | 교구마다 새로(노력) |
|---|---|
| AI 브리지(웹캠 → 숫자 0~9 → USB 시리얼 → 라디오), 수신기 프로토콜, 시뮬레이터 인터프리터·Runner·World, 수업 JSON 스키마·뷰어, 문서·PPT 생성기, 디자인 토큰, Netlify 설정, 시험 틀 | MakeCode 예제(L), 시뮬레이터 API 어댑터(M)·운동학(L)·3D 모형(L), 도우미 규칙·서버 프롬프트·안전 한도(M), 수업 내용·스크린샷(L), 인트로·로고·아이콘(M, `edu-media-pipeline`), 시험의 교구 수치(M) |

자세한 파일 단위 목록과 결합도: `references/inventory.md`.

## 진행 순서 (각 단계 끝에 사용자 확인)

1. **접수** — `references/intake.md`의 체크리스트로 교구 정보를 모은다. 특히 MakeCode 확장 주소·블록 목록, 마이크로비트 장착 방식(버튼이 가려지는지), 시리얼·핀 충돌, 실물 확보 여부. 비어 있는 항목은 "확인 필요"로 표에 남긴다.
   - **확장 소스를 직접 읽는다** — 기억으로 쓰지 않는다. `curl -sL https://raw.githubusercontent.com/<owner>/<repo>/master/pxt.json`(또는 `main`), 그 안의 `files`에 적힌 `.ts`와 `_locales/ko` 번역, README. raw 주소가 막히면 `gh api repos/<owner>/<repo>/contents/<path>`나 `git clone --depth 1`. 그래도 못 읽으면 사용자에게 저장소 접근(또는 파일 첨부)을 요청한다 — 블록 표가 이후 모든 단계의 원천이다.
   - **교구 차이 표**를 만든다: 항목(구동·입출력·센서·LED/소리·버튼 접근·통신/핀·초기화·의존 확장·값 범위) × 기존 교구 × 새 교구 × 사이트에 미치는 영향. 소스로 확인한 사실과 실물로 확인할 것을 구분 표시.
2. **범위 결정** — 시뮬레이터 수준을 고른다(`references/sim-levels.md`): 0 없음(MakeCode 기본 시뮬레이터) / 1 2D 위에서 보기 / 2 3D. 수업 판(2·4·8차시) 중 무엇을 만들지. 이 선택이 작업량의 대부분을 정한다 — 예상 작업량을 표로 보여 주고 고르게 한다.
   - **나눠 출시**를 권한다: 1차 = 실물 점검 예제 + AI 신호등 같은 대표 예제 1개 + 브리지 문구 + 가장 많이 쓰는 차시(보통 4차시) / 2차 = 시뮬레이터·나머지 차시·도우미. 첫 수업 날짜에서 거꾸로 정한다.
   - **저장소 방식**을 정한다: 같은 저장소에 교구 폴더 추가 / 별도 저장소로 복제 / 기존 사이트를 교체. 기존 교구 사이트를 계속 운영하면 공통 부분(브리지·뷰어·생성기) 갱신을 어떻게 나눌지도.
3. **틀 준비** — 새 저장소(또는 브랜치)로 복사. 먼저 교구 종속 값을 `kit/` 폴더로 모으는 정리부터(제안 구조는 `references/inventory.md` 3절). 정리 없이 곧바로 치환하면 다음 교구 때 같은 일을 되풀이한다.
4. **교구 어댑터** — `microbit-sim-builder` 스킬(블록 표 추출기·시뮬레이터 운동학 템플릿·도우미·코드 검사기)로: 블록 표 → 예제 `.ts` → 시뮬레이터 API·장치 감지 → 도우미 규칙 엔진·서버 프롬프트 → 시험 수치. 순서 요약은 `references/phases.md` 4절.
5. **수업 자료** — 같은 수업 흐름(문제 → AI 가르치기 → 마이크로비트 전달 → 교구 움직임 → 안전 점검)을 교구에 맞춰 다시 쓴다. 슬라이드 JSON → `tools/build-slides.mjs`, 문서 → `tools/build-docs.mjs`.
6. **브랜드·미디어** — `edu-media-pipeline` 스킬로: 실물 사진 기반 마스코트 로고, 아이콘 세트, (원하면) 첫 화면 인트로 영상.
7. **점검·배포** — `edu-media-pipeline`의 ⑥: 시험 전부(직렬), 링크·콘솔, 사용자 관점 리뷰 → PR → 배포 → 운영 주소 재확인.

## 지켜야 할 원칙 (이유와 함께)

- **실물 미검증을 '된다'고 쓰지 않는다.** 시뮬레이터는 추정 모델이다. 문서·슬라이드·검증 보고서에 "실물 미검증" 표시와 수업 전 교사 점검표를 남긴다(이전 교구에서 무선 확장 동작은 끝까지 미검증이었다).
- **정책 값은 사용자가 정한다, 시뮬레이터는 그대로 돌린다.** 속도 한도 같은 수업 안전 정책은 교사가 정할 몫이라 스킬이 정하거나 숫자를 바꿔 적지 않는다. 시뮬레이터는 학생이 넣은 값을 **확장의 실제 범위 그대로**(예: 0~255) 재현하고, 도우미에 한도가 있다면 사용자가 바꿀 수 있는 설정값으로 둔다(기존 값을 기본으로 유지). 교구와 무관한 안전장치(계속 움직임 자동 멈춤, 센서 0=못 읽음 처리, 라디오 끊김 감시, 화면 ■ 멈춤)는 틀에 있는 그대로 이어 쓴다.
- **개인정보.** AI 학습 대상은 카드·물건·손 모양(얼굴 금지), 영상은 브라우저 밖으로 안 나감. 도우미 AI는 수업 코드가 있을 때만, 외부 전송을 명시.
- **제조사 존중.** 상표·로고·자료 사용 허락, 확장 라이선스(MIT 등) 고지(`NOTICE.md`), "협력/비공식" 표기를 접수 단계에서 정한다.
- **학교 환경.** 학교망 허용 주소(사이트, `makecode.microbit.org`, 확장을 받는 `github.com`), 저사양 PC(첫 화면은 미리 렌더한 영상), 크롬/엣지 Web Serial.
- **하위 에이전트를 만들 때마다 사용자에게 알린다:** 맡은 일 · 모델 · 사고 깊이(지정 안 했으면 "기본값") · 이유. 넓은 조사·반복 치환·시험 실행·리뷰는 Sonnet(결정적 목록 작업은 Haiku), 설계·안전 규칙·최종 판단은 메인.
