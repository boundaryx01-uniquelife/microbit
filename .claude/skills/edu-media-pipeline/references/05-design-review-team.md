# ⑤ 디자인 리뷰 팀

혼자 만들고 혼자 보면 놓친다. 산출물마다 **관점이 다른 리뷰어 2~3명을 병렬**로 돌리고, 메인이 검증·종합한다.

## 구성(필요한 것만)
| 리뷰어 | 보는 것 | 모델·사고 |
|---|---|---|
| 연속성·브랜드 아트 디렉터 | 앞 영상·실물과의 연결, 마스코트 충실도, 구도 | Sonnet, 기본 |
| 모션·타이포 디자이너 | 박자·이징·정지, 위계·크기·가독성(휴대폰 포함) | Sonnet, 기본 |
| 학생·교사 사용자 | 교실 화면 거리에서 읽히나, 헷갈리는 표현, 버튼 | Sonnet, 기본 |
| 기술 QA | 테스트·링크·콘솔 오류·용량 | Sonnet, 기본 |
| 저장소 정리 | 안 쓰는 파일, 문서와 실제 불일치 | Sonnet(또는 Haiku), 기본 |

만들 때마다 사용자에게 위처럼 "맡은 일·모델·사고 깊이·이유"를 알린다.

## 지시문 요령
- **내 판단을 주지 말고 자료를 준다**(프레임 contact sheet, 전체 크기 대표 프레임, 앞 영상 마지막 프레임, 실물 사진, 원본 코드 경로). 그래야 내 생각에 끌려가지 않은 지적이 나온다.
- 산출 형식: "한 줄 판정 + 영향 큰 순 5개(무엇·어디 t=/슬라이드·왜·구체적 수정값), 칭찬 없이, 300단어 이내".
- 리뷰어가 직접 프레임을 더 뽑을 수 있게 서버 주소·`__seek` 사용법을 알려 준다. 파일은 고치지 않게.

## 종합
- 지적을 스크린샷으로 **직접 확인**한 뒤에만 반영(리뷰어 보고는 주장일 뿐).
- 반영/보류를 표로 사용자에게: 보류는 이유(외부 폰트 필요, 범위 밖, 실물 확인 필요).
- 서로 다른 리뷰어가 같은 문제를 말하면 우선순위를 올린다.
