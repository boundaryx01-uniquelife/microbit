# ② 모션 → 영상 (엔딩·인트로를 mp4로, 첫 화면 등록)

## 0. 무엇이 가능하고 무엇이 아닌가
- 코드(Canvas/SVG)로 잘 되는 것: 모션 그래픽 — 도형·타이포·파티클·로고 애니메이션, 화풍을 흉내 낸 붓결 텍스처, 카메라 이동.
- 안 되는 것: 지브리·실사급 손그림 캐릭터 애니메이션 → 영상 생성 모델(Veo·Kling 등)에 맡기고, 여기서는 컷 설계·이어 붙이기·마감을 한다. 사용자가 그런 품질을 원하면 처음에 이 차이를 분명히 말한다.

## 1. 앞 영상 분석(이어지는 엔딩일 때)
- `scripts/video-frames.sh <video> <dir> 8` → 흐름과 **마지막 프레임**을 본다.
- 실제 사이트에서 3D 합성 등으로 화면이 달라지면(원본 클립에 없는 캐릭터가 얹힘) 마지막 프레임은 **실제 재생 화면**에서 얻어야 한다.
- 이어받을 기준점을 찾는다(예: 마지막 장면의 보름달). 위치·크기를 자동 검출하면(밝은 크림 영역의 현 길이로 원 추정) 화면 비율이 달라도 이어진다.

## 2. 콘셉트(아트 디렉션)
- 한 문장 콘셉트 + 이야기 연결: 예) "별이 모여 눈이 되다" — 밤하늘의 별이 마스코트의 LED 눈 점이 된다.
- 시퀀스 표: 시각 | 일어나는 일 | 이징. 박자 원칙: 한 번에 한 가지가 자리 잡게(눈이 웃은 **뒤에** 제목), 끝에는 정지(hold)와 정리.
- 화풍 잇기: 앞 영상이 그림책 붓결이면 하늘·달도 붓결 텍스처로 칠한다(매끈한 그라디언트는 "웹 그래픽" 티가 난다). 종이 질감 오버레이를 1/12초마다 살짝 흔들면(보일링) 손그림 느낌.

## 3. 구현 규칙
- `render(t)`: 시간 t의 순수 함수. 상태를 프레임 사이에 쌓지 않는다(파티클도 시드 고정 난수 `rnd(i)`로).
- 노출: `window.__seek(t)`, `window.__ready`, `?t=초`, `?cap`(UI 숨김), `?from=<시작 이미지>`.
- 가로·세로 레이아웃: 가상 폭(가로 1920 / 세로 1080) 고정, 높이는 실제 비율로.
- 예시: `assets/ending-example.js` — 마지막 화면 이어받기, 달 검출, 별→LED 점 소용돌이, 실루엣 등장, 눈 패턴(8×8) 키프레임, 제목, 카드 모드(시작 카드가 올라오면 위로 물러남).

## 4. 검토 루프
- 핵심 시각 10~16장을 contact sheet로 → 직접 본다 → ⑤ 리뷰 팀(연속성·브랜드 / 모션·타이포) → 종합해 반영/보류를 사용자에게 표로.

## 5. 렌더와 인코딩
- 앞부분이 3D/영상 합성이면: 프레임마다 영상 `currentTime`을 정확히 맞추고(seeked 대기) 그 자리에서 캔버스를 읽는다(`scripts/render-frames.js --canvas … --webgl`). Range 서버 필수.
- 엔딩은 앞부분 마지막 프레임을 `?from=`으로 넘겨 이어 렌더.
- `scripts/frames-to-mp4.sh frames out.mp4 30 24` — 종이 결 보일링이 있으면 용량이 커지므로 crf 24~26, 1280폭 권장(38초 ≈ 4.5MB).

## 6. 첫 화면 등록
- 실시간 3D보다 **미리 렌더한 mp4 한 편**이 저사양 학교 PC에 안전하다(3D 엔진을 불러오지 않음).
- `<video muted playsinline preload="auto">` + 자막·진행 막대는 `video.currentTime`을 따라(rAF). 영상이 끝나면 엔딩 마지막 장면을 같은 그림으로 이어받는 캔버스가 카드 모드로 정리 → 시작 카드.
- 건너뛰기·같은 탭 재방문·움직임 줄이기·영상 실패 → 엔딩 정지 화면 + 시작 카드.
- 세로 화면: `object-fit: contain` + 같은 영상을 흐리게 키운 배경(세로일 때만 `preload` 켜기) + 자막 크게.
- 다시 만드는 도구를 저장소에 남긴다(예: `tools/render-intro.js`, `INTRO_TEST=1` 몇 장만 시험 모드).
