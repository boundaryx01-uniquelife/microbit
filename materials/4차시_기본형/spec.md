## 실물에서 확인된 사실 (반드시 반영, 틀리면 수업이 안 됨)
(2차시 spec의 사실 + 4차시용 추가)
- 로보독 **등에 꽂은 마이크로비트의 A·B 버튼은 가려져서 누를 수 없다.** 로보독 쪽 입력 = **본체 버튼(아래쪽 전원 스위치 옆)**. 코딩 블록은 **"로보독 버튼이 눌렸는가"**.
- 마이크로비트가 로보독의 **뇌**. 빼면 로보독은 눈만 깜빡이고(대기) 아무것도 안 함. 꽂고 빼는 것은 전원을 끈 상태에서.
- 배터리가 약하면 다리가 떨리거나 따로 노는 것처럼 보임 → 수업 전 충전·점검 필수.
- 충전 전용 USB 케이블이면 PC에 MICROBIT 드라이브가 안 보임 → **데이터용 케이블**.
- 사이트: 시뮬레이터 https://microbit-bridge.netlify.app/sim/ , AI 브리지 https://microbit-bridge.netlify.app/ai.html
- **코딩은 시뮬레이터의 블록 편집기에서 한다.** 로보독 확장이 이미 들어 있어 왼쪽 메뉴 "로보독"을 바로 쓴다(확장을 학생이 추가하지 않는다 — docs/02의 "확장 추가" 5분은 "편집기 열기"로 바꿈). 블록을 고치면 약 1초 뒤 오른쪽 로보독(3D 기본, [2D 보기] 탭)이 그대로 움직인다. 마이크로비트에 넣을 때는 편집기 아래 **[다운로드]** → MICROBIT 드라이브.
- 시뮬레이터 오른쪽 패널의 "로보독 본체 버튼 누르기"로 본체 버튼을 흉내 낸다. 예제 목록에서 "2. 규칙으로 반응하기 (거리센서)", "4. 우리 모둠 AI 로보독 (틀)"을 불러 [이 코드로 바꾸기]로 블록에 넣는다. 같은 컴퓨터의 AI 브리지가 인식한 번호는 시뮬레이터 로보독에 라디오처럼 전달된다(다운로드 전 시험용).
- 블록 편집기가 안 열리면(학교망이 makecode.microbit.org 차단) 60초 뒤 글자 코드 탭으로 바뀜 → 교사 시연 + 글자 코드 붙여넣기가 플랜 B.
- 속도 **30 이하** (예제는 걷기 25). 걷기는 **바닥이나 울타리 안**(거리센서는 책상 끝을 못 봄). 책상 위 걷기 금지.
- 거리센서 값 **0 = 못 읽음 → 멈춤**(예제 02). 값 단위·범위는 실물에서 먼저 확인(시뮬레이터는 cm, 없으면 255). 예제 02의 기준값 초기값은 20.
- `01_hello-robodog`: 본체 버튼을 누를 때마다 1 인사(파란 불·"안녕" 소리·인사 자세) → 2 조금 걷기(초록 불, 1초) → 3 앉기(주황 불) → 다시 1.
- `02_distance-rule`: 켜자마자 걷지 않음. 본체 버튼 = 걷기 시작/멈춤. 멈춘 동안에도 몸통 불빛으로 거리 표시(빨강 = 가까움, 초록 = 멂, 눈은 감음). 걷는 중 가까우면 멈춤 + 빨간 불 + 찢눈 + "비켜" 소리, 멀면 초록 불 + 속도 25 전진. "가까움기준" 숫자 하나를 모둠이 바꾼다.
- `00_bridge-receiver`: PC에 꽂는 USB 마이크로비트. 켤 때 B1(모둠번호) 표시. A = 멈춤 잠금, B = 풀기(손에 있으니 누를 수 있음).
- `03_ai-traffic-dog`: 라디오 숫자로 행동. 1 빨강 = 멈춤 + "비켜!" + 빨간 불 / 2 노랑 = 멈춰서 기다림 + 주황 불 / 3 초록 = 속도 25 출발 + 초록 불 / 0·4(배경) = 멈춤·눈 감음. **2초 동안 신호가 없으면 스스로 멈춤.** 본체 버튼 = 멈춤 잠금 ↔ 풀기(잠그면 눈에 X). 켤 때 R1(모둠번호) 표시.
- `04_ai-team-template`: 03과 같은 안전장치(2초 감시·본체 버튼 잠금) + "번호에맞게행동하기" 안의 1~3번 TODO 행동(예시: 1 빨간 불+으르렁, 2 파란 불+인사, 3 초록 불+하트 눈), 0·4 = 준비 자세. 학생은 1~3번 행동만 바꾼다.
- 멈추는 방법 3가지: ① AI 브리지 [■ 멈춤] 또는 Esc ② 로보독 본체 버튼(멈춤 잠금) ③ 로보독 전원 스위치. (+ 자동: 신호 2초 끊기면 멈춤, 브리지 창을 내려도 멈춤)
- 확신 %는 "맞을 확률"이 아니라 "AI가 자신 있어 하는 정도". 처음 보는 주황 카드를 노랑 100%로 답하는 것이 실제로 확인됨(assets/ai_orange.png).
- 로보독 마이크로비트에는 '음악' 블록을 쓰지 않는다(로봇 통신 핀과 겹칠 수 있음).
- 로보독 마이크로비트가 모둠당 2개(01·02·04용 + 03용)면 라벨로 구분. 다운로드·재연결에 모둠당 3~5분이 걸리므로 수업 중 마이크로비트 교체·재다운로드는 최소화.
- 블록 이름은 편집기 화면 그대로 쓴다. 확인된 이름: "로보독 버튼이 눌렸는가", "로보독 자세를 … 취하기". 나머지(표정·효과음·몸통 불빛·걷기·멈추기·거리센서 값)는 로보독 메뉴의 한국어 블록 이름을 수업 전에 편집기에서 확인해 활동지·슬라이드 문구를 맞춘다(미확인).

## A. 수업 슬라이드 (PPT 16:9, 46장, 슬라이드마다 발표자 노트 = 교사 대본)

### 1차시 — 로보독과 첫 만남
1. **로보독과 첫 만남** [cover] — 부제 "피지컬 AI 교실 1차시" | 그림 story_hello.png
   노트: [0'] 진행: 배부 전에 이 화면만 띄워 둡니다. 로보독·마이크로비트·데이터용 USB 케이블은 아직 나눠 주지 않습니다.
2. **오늘의 목표** [goals] — 피지컬 AI가 무엇인지 말할 수 있어요 · 로보독의 눈·뇌·몸을 찾을 수 있어요 · 블록으로 인사 순서를 만들어 로보독에게 보내요
   노트: [0'~1'] 진행: 목표 세 줄을 함께 읽습니다. 마지막 목표(블록 코딩)가 오늘의 중심 활동임을 알려 줍니다.
3. **안전 약속 3가지** [points] — 떨어뜨리지 않기(책상 가장자리에 두지 않아요) · 천천히(속도는 30 이하로 정해요) · 위험하면 바로 전원 끄기(전원 스위치를 꺼요)
   노트: [준비 5'] 발문: "로봇이 책상에서 떨어지면 어떻게 될까요?" / 예상 답: 부서져요, 다쳐요 / 진행: 모둠별 로보독 배부, 전원 켜기, 활동지 1쪽 안전 약속에 서명 / 주의: 배터리 확인(전날 점검 예제로 몸통 불빛 초록 확인). 책상 위에서는 로보독을 걷게 하지 않습니다.
4. **먼저 보세요** [question] — 부제 "선생님 로보독이 인사해요" | 큰 글 "이 로봇은 어떻게 알고 움직였을까?" / 선생님 로보독이 인사해요 | 그림 story_walk.png
   노트: [시연·도입 3'] 진행: 교사 로보독으로 본체 버튼을 눌러 인사 장면을 시연 / 발문: "누가 로봇에게 인사하라고 알려 줬을까요?" / 예상 답: 버튼, 프로그램, 사람이 시켜서 / 진행: "오늘은 여러분이 직접 알려 줄 거예요"라고 연결
5. **피지컬 AI = 눈 + 뇌 + 몸** [flow] — 눈(센서·카메라: 보고 느끼기) → 뇌(마이크로비트·AI: 판단하기) → 몸(모터·LED·스피커: 움직이기) | 띠: 사람도 눈으로 보고 → 머리로 생각하고 → 몸으로 움직여요
   노트: [개념 2'] 발문: "사람은 무엇으로 보고, 무엇으로 생각하고, 무엇으로 움직이나요?" / 예상 답: 눈, 뇌, 손과 발 / 진행: 사람과 로봇을 나란히 비교. 로봇 청소기·자율주행차를 예로 한 줄씩 말해 줍니다.
6. **로보독 몸 살펴보기** [image] — 눈 LED(두 개)와 몸통 LED · 거리센서(앞쪽 아래)와 카메라(눈 사이) · 마이크로비트 자리(등) · 본체 버튼(아래쪽, 전원 스위치 옆) · 전원 스위치 | 강조: 활동지 2쪽에서 실물을 찾아 ✔ 하세요 | 그림 sim_robodog3d.png
   노트: [부품 관찰 5'] 진행: 활동지 2쪽 1번. 모둠이 실물에서 부품을 찾아 체크하고 '눈·뇌·몸 중 무엇인지' 적습니다. / 주의: 다리를 손으로 억지로 꺾지 않기(모터 고장). 로보독을 들 때는 몸통을 두 손으로.
7. **마이크로비트 = 로보독의 뇌** [points] — 등에 꽂으면 프로그램대로 움직여요 · 꽂으면 A·B 버튼은 가려져요(그래서 "본체 버튼"을 써요) · 빼면? 눈만 깜빡이고 쉬어요(뇌가 없으니까요)
   노트: [부품 관찰 이어서] 진행: 전원을 끈 상태에서 마이크로비트를 뺐다 꽂아 보여 줍니다. 학생이 직접 뺄 때도 반드시 전원 끈 상태. / 주의: 본체 버튼 위치(아래쪽, 전원 스위치 옆)를 손가락으로 짚어 보게 합니다.
8. **코딩 화면 열기** [image] — 주소: microbit-bridge.netlify.app/sim/ · 왼쪽이 블록 코딩 화면 · 오른쪽에서 로보독이 미리 움직여 봐요 · 2D 보기·3D 보기를 눌러 바꿔 봐요 | 강조: 로보독 블록은 이미 들어 있어요 | 그림 sim_page.png

   노트: [연결 이해 4'] 진행: 칠판에 같은 그림을 그리며 설명합니다. "초록 카드를 보면 AI가 3번이라고 정하고, USB 마이크로비트가 3을 무선으로 보내요" / 발문: "AI 브리지에서 로보독까지, 중간에 무엇을 거치나요?" / 예상 답: 마이크로비트, 라디오
28. **모둠 역할** [cards] — 카드 담당: 카메라 앞에서 카드 보여 주기 / 컴퓨터 담당: 사진 모으기·연결, ■ 멈춤 / 로봇 담당: 로보독 위치·전원, 본체 버튼 멈춤 잠금 / 기록 담당: 활동지 쓰기 | 아래: 3명 모둠은 카드 담당이 기록도 함께해요
   노트: [준비] 진행: 역할을 정하고, 4차시에서는 역할을 바꿔 해 보자고 예고. / 주의: 카메라에는 카드와 물건만 비춥니다. 얼굴이 나오지 않게.
29. **1단계: AI 가르치기** [image] — 1 빨강 · 2 노랑 · 3 초록 · 4 배경(빈 책상) · 종류마다 20장 이상, 비슷한 수로 · 카드를 조금씩 움직이고 기울이며 · 꾹 누르면 1초에 4장씩 모여요 | 강조: 사진 모으는 동안 로보독은 멈춰 있어요(정상) | 그림 ai_start.png
   노트: [AI 학습 10'] 주의: 같은 자세로만 모으면 AI가 쉽게 헷갈립니다. 배경은 아무것도 없는 책상. 종류별 수가 크게 다르면 한쪽으로 쏠림 경고가 뜹니다. / 발문: "사진을 다양하게 모으면 왜 좋을까요?" / 예상 답: 여러 모양을 알게 돼요
30. **2단계: 로보독에게 보내기** [table] — 1 빨강 → 멈추고 "비켜!" / 2 노랑 → 멈춰서 기다려 / 3 초록 → 천천히 출발 / 4 배경 → 멈춤 | 그림 ai_green.png
   노트: [시험 8'] 진행: [USB 마이크로비트 연결] → "BBC micro:bit" 선택 → 카드 보여 주기. 카드를 바꿔 가며 반응 확인. / 주의: 로보독은 바닥이나 울타리 안에서만. 시간이 남는 모둠만(선택) '신호에반응하기'에서 한 신호의 행동을 바꿔 다시 다운로드 — 모둠당 3~5분 걸리므로 기본은 교사 시연. 이 차시에는 실험(주황 카드 등)을 시험 시간에 짧게 해 봅니다.
31. **멈추는 방법 3가지** [points] — 화면 [■ 멈춤] 또는 Esc · 로보독 본체 버튼(눈에 X가 떠요. 다시 누르면 풀려요) · 전원 스위치 | 아래: 신호가 2초 끊기면 로보독이 스스로 멈춰요
   노트: [시험 중] 진행: 세 가지를 모둠마다 한 번씩 연습. / 발문: "왜 멈추는 방법이 여러 개 필요할까요?" / 예상 답: 하나가 안 될 수 있어서 / 주의: 본체 버튼은 로보독 아래쪽(전원 스위치 옆). 꽂은 마이크로비트의 A·B는 가려져 있음.
32. **AI를 헷갈리게 해 봐요** [image] — 처음 보는 주황 카드를 보여 줘요 · 카드를 손으로 반쯤 가려요 · 불을 어둡게 해요 | 강조: 주황을 "노랑 100%"라고 했어요. 자신 있게 틀릴 수 있어요 | 그림 ai_orange.png
   노트: [시험 중 짧게 3'] 진행: 예상을 먼저 말하고 실험. / 발문: "AI가 100%라고 했는데 틀렸어요. 왜 그럴까요?" / 예상 답: 주황을 배운 적이 없어서, 노랑과 비슷해서 / 교사 지식: 확신 %는 '맞을 확률'이 아니라 AI가 자신 있어 하는 정도. 가리거나 어두우면 '잘 모르겠어요'가 떠 멈추는 경우가 많음. / 주의: 실험할 때도 로보독 앞은 비워 두기.
33. **활동지 B: 규칙 로봇 vs AI 로봇** [table] — 1 누가 기준을 정했나? → 규칙: 사람이 숫자(기준값) / AI: 사람이 고른 사진과 이름표 / 2 무엇을 잘하나? → 규칙: 정한 것(거리) / AI: 보여 준 것(그림) / 3 언제 틀리나? → 규칙: 기준을 잘못 정하면 / AI: 처음 보는 것·사진이 부족할 때
   노트: [비교표 5'] 진행: 모둠이 활동지 B(4쪽)의 빈 칸을 먼저 쓰고, 이 화면으로 확인. 화면의 오른쪽 글은 예시이므로 학생 표현을 우선합니다. / 교사용: 두 방식 모두 사람의 선택이 들어갑니다(규칙은 기준값, AI는 어떤 사진을 어떤 이름으로 보여 줄지). ◎ 기준: 두 방식 모두 사람의 선택이 들어감을 포함해 설명.
34. **오늘의 핵심** [core] — AI는 보여 준 예시(데이터)로 배워요 · 처음 보는 것도 아는 것 중 하나로 자신 있게 틀릴 수 있어요 · 그래서 사람의 확인과 멈춤 장치가 필요해요 · 다음 시간: 우리 모둠 AI 로보독을 만들어요
   노트: [정리 5'] 진행: 소리 내어 읽기. AI 브리지 [모두 지우기], 로보독 전원 끄기, 충전기 연결. 3차시 마지막에 4차시 주제 후보를 안내하면 좋습니다.

### 4차시 — 우리 모둠 AI 로보독
35. **우리 모둠 AI 로보독** [cover] — 부제 "피지컬 AI 교실 4차시" | 그림 story_stop.png
   노트: [0'] 진행: 모둠 주제용 그림 카드·학생 물건 준비. 로보독에는 04 틀 마이크로비트를 미리 넣어 두거나, 시뮬레이터에서 학생이 불러옵니다. AI 브리지가 "AI 준비 완료"인지 확인.
36. **오늘의 목표** [goals] — 문제를 고르고 AI 로보독을 설계해요 · 카드를 학습시키고 행동을 코딩해요 · AI가 틀릴 때를 생각하고 안전하게 만들어요
   노트: [0'~1'] 진행: 목표 읽기. 오늘은 활동지 C(설계표)가 중심. 모둠 역할을 3차시와 바꿔서 해 보도록 안내.
37. **문제 고르기 (모둠 주제)** [cards] — 급식 알레르기 탐지견: 땅콩 그림 · 우유 그림 · 안전한 음식 그림, 그림 카드(교사 출력) / 교실 도우미견: 손바닥 펴기 · 정리 시간 카드 · 쉬는 시간 카드, 카드 2장 + 손(얼굴 X) / 내 물건 알아보는 반려견: 내 필통 · 친구 필통 · 지우개, 학생 물건 / 위험 알림견: 위험 표지 · 미끄럼 주의 · 안전 표지, 그림 카드 | 아래: 사람 얼굴은 학습하지 않아요. 손은 얼굴이 안 나오게 손만 비춰요
   노트: [배부·문제 선택 5'] 진행: 모둠이 4개 중 한 주제를 고르고 그림 카드를 받습니다(같은 주제 겹쳐도 됨). / 주의: 얼굴·친구 맞이 주제 금지. '손바닥 펴기'는 카메라에 손만 보이게. 학생 물건 주제는 개인 물건을 다루므로 예의를 지키도록.
38. **설계표 예시: 급식 알레르기 탐지견** [table] — 1 땅콩 그림 → 멈추고 으르렁 + 빨간 불 (위험!) / 2 우유 그림 → 멈추고 "기다려" + 주황 불 (확인!) / 3 안전한 음식 그림 → 하트 눈 + 초록 불 (안심) / 4 배경(아무것도 없음) → 준비 자세 (기본)
   노트: [설계 7'] 진행: 예시는 하나의 보기일 뿐, 모둠은 자기 주제로 활동지 C를 채웁니다. 4번은 항상 배경 → 준비 자세(기본). / 발문: "AI가 무엇을 보면, 로보독은 무엇을 하나요? 왜 그렇게 정했나요?" / 예상 답: 위험하면 알려 주려고, 안전하면 안심시키려고
39. **활동지 C: 설계표 쓰기** [points] — 돕고 싶은 사람·상황을 한 줄로 · 번호 1~3: AI가 보는 것 → 로보독 행동 → 왜?(행동 = 색 · 소리 · 표정 · 자세) · 번호 4는 배경 → 준비 자세 · 코드 스케치 3질문과 "틀리면 어떻게?"까지
   노트: [설계 7' 이어서] 진행: 기록 담당이 쓰고 모둠이 함께 의견 모으기. 코드 스케치 3질문(순서·블록·'만약 ~라면' 나누기)은 1·2차시 활동과 연결: "순서는 1차시, 만약~라면은 2차시". / 주의: 행동은 속도 30 이하. 빨리 끝난 모둠은 '틀리면 안전하게'를 구체적으로(예: 알레르기 그림을 못 알아보면 선생님께 물어보기).
40. **AI에게 모둠 카드 가르치기** [image] — 1·2·3 = 모둠 카드, 4 = 배경(빈 책상) · 종류마다 20장 이상, 움직이며 · 얼굴이 나오지 않게 카드만 비춰요 | 강조: 3차시와 같아요. 이번에는 우리 카드예요 | 그림 ai_start.png
   노트: [AI 학습·코딩 15' 중 5'] 진행: 3차시에서 한 방법을 떠올리며 모둠이 카드를 학습. 배경도 꼭 포함. / 주의: 로보독은 학습 중 멈춰 있음(정상). 사진을 모은 뒤 [USB 마이크로비트 연결].
41. **행동 코딩: 틀의 빈칸 채우기** [code] — 1) 시뮬레이터 예제 목록에서 "4. 우리 모둠 AI 로보독 (틀)" 예제를 불러와요 2) "만약 번호 = 1이라면" 안의 행동 블록을 설계표 1번대로 바꿔요 [색 · 소리 · 표정 · 자세] 3) 2번, 3번도 같은 방법으로 바꿔요 4) 모둠번호를 우리 번호로 바꿔요(두 마이크로비트가 같아야 해요) 5) 안전 블록(2초 감시 · 본체 버튼 잠금 · 속도 30 이하)은 지우지 않아요 | 팁: 바꿀 곳은 1·2·3번 행동 블록뿐! 시뮬레이터에서 AI 브리지 결과로 먼저 시험해도 돼요.
   노트: [AI 학습·코딩 15' 중 7'] 진행: 틀 예제에는 1~3번 행동 예시(소리·불빛·자세)가 들어 있으므로 설계표에 맞게 블록을 바꾸게 합니다. 시뮬레이터에서 같은 컴퓨터의 AI 브리지 결과가 라디오처럼 전달되므로 다운로드 전에 확인 가능. / 주의: 로보독 마이크로비트에서는 '음악' 블록 금지. 안전 블록을 지운 모둠은 예제를 다시 불러오게 함(루브릭: 안전장치 유지). (요청 스크린샷: 04 틀이 블록으로 불러와진 편집기 화면, 1~3번 행동 블록 영역 표시)
42. **시험하고 고쳐요** [flow] — 카드 보여 주기(AI 답 확인) → 로보독 행동 보기(설계표와 같은가?) → 고치기(사진 더 모으기 또는 블록 바꾸기) ↺ | 띠: 안 맞으면: AI 문제(사진) 인가 · 코드 문제(블록) 인가?
   노트: [AI 학습·코딩 15' 중 3'] 진행: 시험 → 고치기를 한 번이라도 해 본 모둠은 활동지에 적습니다. / 발문: "틀렸을 때 AI 문제인지, 코드 문제인지 어떻게 알 수 있나요?" / 예상 답: AI 화면의 답이 틀리면 사진 문제, 답은 맞는데 행동이 틀리면 코드 문제 / 주의: 로보독은 바닥이나 울타리 안. 다운로드·재연결에는 3~5분이 걸리니 고칠 때는 시뮬레이터에서 먼저.
43. **윤리 점검 3가지** [checklist] — 사람 얼굴을 찍지 않았나? · AI가 틀리면 누가 확인하나? · 틀렸을 때 위험하지 않게 멈추나?
   노트: [윤리 점검 4'] 발문: "AI가 틀리면 누가 확인하나요? 틀렸을 때 로보독은 어떻게 멈추나요?" / 예상 답: 선생님, 사람이 직접, 본체 버튼·■ 멈춤·2초 신호 끊김 / 진행: 모둠이 체크하고 활동지 C의 '틀리면 어떻게 안전하게?'를 완성. ◎ 기준: 얼굴 미촬영, 오류 시 멈춤·사람 확인을 설계에 반영.
44. **모둠 시연** [question] — 부제 "한 모둠 1분: 주제 → 시연 → 칭찬 한마디" | 큰 글 "우리 모둠 AI 로보독을 보여 줘요" / 한 모둠 1분: 주제 → 시연 → 칭찬 한마디 | 그림 story_walk.png
   노트: [시연 5'] 진행: 1분씩 시연. 모든 번호를 한 번 보여 주고, 청중은 '좋았던 점'을 한 가지 말합니다(칭찬 한마디). / 주의: 시연 중 로보독 앞을 비우고 멈춤 담당 지정. 시간이 부족하면 대표 3모둠 + 나머지는 교실 순회.
45. **4차시를 마치며** [core] — 규칙은 사람이 정한 숫자로, AI는 보여 준 예시로 움직여요 · 둘 다 사람의 선택이 들어가요 · AI는 틀릴 수 있어서 멈춤 장치와 사람 확인이 필요해요 · AI를 쓸 때 사람의 얼굴과 정보를 지켜요
   노트: [정리 5'] 진행: 소리 내어 읽기. 학생이 하나씩 '오늘 배운 것'을 말하게 해도 좋습니다.
46. **마무리 정리** [checklist] — AI 브리지 [모두 지우기] · 로보독 전원 끄기 · 마이크로비트 분리·라벨 확인 · 충전기 연결 · 활동지 자기 점검
   노트: [정리·회수 4'] 진행: 데이터 지우기는 개인정보 습관. 교사 관찰 체크리스트(규칙 vs AI 차이 설명·조건문·라디오 제어·데이터 개선·윤리·안전)에 기록. / 주의: 로보독이 뜨거우면 충전 전에 잠시 식히기.

모든 쪽 머리: "피지컬 AI 교실 · 로보독" + 오른쪽 "모둠 ____  이름 ________". 쓰는 칸은 넉넉한 밑줄/빈 칸(손글씨). 정답은 교사용에만.

1쪽 **로보독 안전 약속** (1차시 시작) — 체크박스 5개 (2차시 spec 1쪽과 동일):
□ 로보독을 책상 가장자리에 두지 않고, 떨어뜨리지 않겠습니다. □ 로보독 속도는 30 이하로 정하겠습니다. □ 위험하면 바로 멈추겠습니다(AI 활동: 화면 ■ 멈춤 또는 로보독 본체 버튼 / 그 밖의 활동: 로보독 전원 끄기). □ 카메라로 친구나 내 얼굴을 찍지 않겠습니다. 카드와 물건만 보여 주겠습니다. □ 수업이 끝나면 AI 학습 데이터를 '모두 지우기' 하겠습니다. / 서명 칸.

2쪽 **[1차시] 로보독 관찰지** (2차시 spec 2쪽 재사용)
1. 표: 부품 | 찾았나요 | 하는 일(눈·뇌·몸 중 무엇?) — 눈 LED / 몸통 LED / 거리센서 / 카메라 / 마이크로비트 자리 / 본체 버튼 / 전원 스위치 (sim_robodog3d.png 작게)
2. 오늘 내가 만든 인사 장면(코드 순서): 1번째 ____ 2번째 ____ 3번째 ____ 4번째 ____
3. 출구 질문: 피지컬 AI는 (   )으로 보고 (   )로 판단하고 (   )으로 움직이는 로봇이다. / 오늘 로보독은 스스로 판단했나요? 예 / 아니요, 왜? ____
   (교사용 정답: 눈 / 뇌 / 몸. "아니요, 우리가 정한 순서대로 움직였다.")

3쪽 **코딩 미션 카드** — 점선으로 두 장(1차시·2차시)
[1차시 미션: 인사 순서 바꾸기]

- 미션 2: 인사 앞에 몸통 불빛 색을 넣어 보기. 고른 색 ____
- 미션 3: 나만의 인사 장면(블록 4개 이상, 속도 30 이하). 순서: ____ → ____ → ____ → ____ → 준비 자세
- 확인 칸: □ 시뮬레이터에서 됐다 □ 로보독에서 됐다 □ 준비 자세로 끝났다
[2차시 미션: 가까움 기준값 정하기]
- 손을 가까이 했을 때 몸통 불빛이 빨강으로 바뀐 거리: 1회 ____ 2회 ____ 3회 ____ (단위는 거리센서 값)
- 우리 모둠 "가까움 기준값" = ____ (이유: ____)
- 바꾼 뒤 걸어 보기: 기준값 ____ 일 때 멈춘 위치 ____ / 더 크게(또는 작게) 해 봤더니 ____
- 지키기: □ 속도 30 이하 □ 바닥/울타리 안 □ 안전 블록은 지우지 않음

4쪽 **[2차시] 규칙 로봇 기록** — 거리 실험 표(손 가까이/멀리 → 몸통 불빛 색), "규칙으로 쉽게 되는 일은? ____ / 규칙으로 하기 어려운 일은? (땅콩 그림과 우유 그림 구분 등) ____" (정답 없음, 생각 열기). 아래에 **[활동지 B] 규칙 로봇 vs AI 로봇** 표는 3차시에 쓰도록 비워 둠(5쪽으로 이어짐).

5쪽 **[3차시] 활동지 A + 활동지 B**
- 활동지 A(2차시 spec 3쪽의 1~5번과 같음): 낱말 풀이(데이터 / 확신 / 멈춤 장치) · 모은 사진 수(빨강·노랑·초록·배경) · 실험 결과 표(빨강 기준 / 주황 처음 보는 색 / 반쯤 가림 / 어둡게 / 옆 모둠 카드) · 확신이 높은데 틀린 적 · 안내견이 틀린다면 · 더 믿을 수 있게(데이터·멈춤 장치·사람 확인)
- 활동지 B 3×3 표(docs/04 그대로): 행 = 누가 기준을 정했나? / 무엇을 잘하나? / 언제 틀리나?, 열 = 규칙 로봇(거리센서) / AI 로봇(카메라+학습). 아래 한 줄: "두 방식에서 사람이 한 선택은 무엇인가요? ____" (규칙: 기준값, AI: 사진·이름표)

6쪽 **[4차시] 활동지 C — 우리 모둠 AI 로보독 설계표** (docs/04 그대로)
모둠 ___ 주제 ___ / 돕고 싶은 사람·상황 ___ / 표: 번호 | AI가 보는 것(카드·물건) | 로보독 행동(색·소리·표정·자세) | 왜? — 1·2·3 빈칸, 4 = 배경(아무것도 없음) → 준비 자세 → 기본 / 코드 스케치 3질문(① 순서 ② 블록 ③ '만약 ~라면' 나누기) / AI가 틀리면 어떻게 안전하게 할까요? ___
