# 교사용 운영 가이드 — AI 개념, 학교 PC 점검, 문제 해결

## 1. 교사가 알아야 할 AI 개념 (AI 브리지 동작 원리)

AI 브리지는 두 단계로 동작합니다.

1. **특징 뽑기(전이학습)**: 이미 수많은 사진으로 학습된 모델(MobileNet)이 카메라 화면을 숫자 1,280개짜리 "특징"으로 바꿉니다.
   이 모델은 수업 중에 다시 학습하지 않습니다.
2. **비교해서 답하기(k-최근접 이웃, KNN)**: 학생이 모은 사진들의 특징을 기억해 두었다가,
   새 화면과 **가장 비슷한 k장**(기본 10장, 적게 모은 종류가 있으면 그 수만큼)을 찾아 **가장 많은 이름**으로 답합니다.

| 화면 표현 | 정확한 의미 |
|---|---|
| "사진 모으기" = 학습 | 예시를 저장하는 것. KNN은 따로 훈련 과정이 없음 |
| 확신 % | 가까운 k장 중 같은 이름의 비율(투표 비율). **맞을 확률이 아님** |
| 확신 기준 | 이 비율이 기준보다 낮으면 로보독에 0(멈춤)을 보냄 |

꼭 짚을 점
- **확신이 높아도 틀릴 수 있습니다.** 배우지 않은 것(예: 파란 카드)도 아는 것 중 가장 비슷한 것으로 100% 답할 수 있습니다(테스트에서 실제 확인).
  그래서 '배경' 종류와 멈춤 장치, 사람의 확인이 필요합니다.
- **사진 수 ≠ 다양성**: 꾹 누르면 1초에 4장씩 비슷한 사진이 쌓입니다. 카드를 움직이고 기울이며 모으게 하세요.
- **종류별 사진 수 균형**: 한 종류만 많으면 그쪽으로 답이 쏠릴 수 있습니다(화면에 경고 표시).
- **용어**: 조명·처음 보는 색에 약한 것은 '일반화' 문제, 한 사람 손·한 조명에서만 모은 것은 '데이터 치우침(편향)'입니다.

## 2. 학교 PC 점검표 (수업 전 1회)

| 점검 | 방법 | 안 될 때 |
|---|---|---|
| 브라우저 | **크롬 또는 엣지(최신)** 권장. 웨일은 미검증 | 크롬/엣지 설치 요청 |
| 기기 | **윈도우·맥 PC** 권장. 크롬북·안드로이드는 미검증, 아이패드는 USB 연결(Web Serial) 불가 | PC실 사용 |
| AI 브리지 주소 | **https://microbit-bridge.netlify.app/ai.html** 을 열어 "AI 준비 완료" 확인 | 막히면 정보부에 `microbit-bridge.netlify.app` 허용 요청(모델·라이브러리 모두 이 주소에서 받음) |
| 시뮬레이터 블록 코딩 | https://microbit-bridge.netlify.app/sim/ 에서 블록 편집기가 1분 안에 열리는지 | `makecode.microbit.org` 와 MakeCode가 쓰는 주소(확장을 받는 `github.com` 등 — 정보부가 브라우저 개발자 도구로 확인)도 허용 필요. 막히면 60초 뒤 **글자 코드(JavaScript)** 탭으로 바뀜 |
| 로보독 도우미(AI) | 시뮬레이터 위 도우미 배지가 'AI 도우미'인지 | 교사가 Netlify에 키를 넣은 경우만. 학생 입력이 외부 AI 서버로 전송되므로 학교 정책 확인. 키가 없으면 '규칙 도우미'(전송 없음) |
| 카메라 | [카메라 켜기] → 허용 | 브라우저 주소창 왼쪽 자물쇠 → 카메라 허용 |
| USB 마이크로비트 | [USB 마이크로비트 연결] → "BBC micro:bit" 선택 | 데이터용 케이블인지, MakeCode 탭이 연결을 잡고 있지 않은지 확인 |
| MakeCode 다운로드 | makecode.microbit.org에서 다운로드 → MICROBIT 드라이브에 복사 | USB 저장장치 차단 정책이면 정보부에 예외 요청, 또는 교사 PC에서 일괄 다운로드 |
| 로보독 연결·배터리 | `makecode/00_check-robodog.ts`를 내려받아 꽂고 켜기 → 눈 하트(통신), 몸통 초록(배터리), 본체 버튼마다 앉기↔서기 | 아래 '자주 생기는 문제' 참고 |
| 재부팅 후 다시 열기 | PC를 껐다 켜도(복원 프로그램이 있어도) 사이트가 다시 열리는지 | AI 모델은 배포 사이트에 함께 들어 있어 매번 다시 받아도 됨(약 8MB) |

※ 파일을 더블클릭해서 열면(file://) 모델을 인터넷(tfhub/kaggle)에서 받아 옵니다. 학교망에서 막힐 수 있으니 **배포 주소로 여는 것을 권장**합니다.

## 3. 안전 장치 정리

| 장치 | 동작 |
|---|---|
| 브리지 ■ 멈춤 / Esc | 다시 누를 때까지 0(멈춤)을 계속 보냄 |
| 확신 기준 미달 | 잠시 헷갈리면 0을 보냄 |
| 사진 모으는 중·데이터 지움·카메라 꺼짐 | 0을 보냄 |
| 브리지 창을 내리거나 다른 탭 | 0을 보냄 |
| 같은 번호 반복 전송 | 약 0.5초마다 다시 보냄 |
| 로보독 | 로보독 본체 버튼(전원 스위치 옆) = 멈춤 잠금 ↔ 풀기(잠그면 눈에 X), 2초 동안 신호가 없으면 멈춤 |
| USB 마이크로비트 | A=멈춤 잠금(0을 계속 보냄), B=풀기 |

## 4. 자주 생기는 문제

3분 안에 해결되지 않으면 `01_소개형_2차시.md`의 **플랜 B**(시뮬레이터·교사 PC 시연)로 바꾸고 쉬는 시간에 원인을 찾으세요.

| 증상 | 확인할 것 |
|---|---|
| 로보독이 아무 반응이 없음 | 모둠번호가 두 마이크로비트에서 같은지(PC용은 켤 때 B1, 로보독은 켤 때 눈에 1처럼 모둠번호 숫자, 또는 라벨), 로보독 전원, 브리지 '지금 보내는 번호' |
| 다른 모둠 로보독이 움직임 | 모둠번호 중복 |
| "AI 불러오기 실패" | 인터넷/학교망 차단, 배포 주소로 열었는지, 새로고침 |
| 연결 창에 마이크로비트가 없음 | 데이터용 케이블, 다른 탭(MakeCode)의 연결 끊기 |
| 계속 '잘 모르겠어요' | 사진을 더 다양하게, 확신 기준을 60%로 |
| 엉뚱한 답을 자신 있게 함 | 배경 종류 추가, 헷갈리는 물건도 학습시키기 |
| 로보독이 걷다가 주저앉음·떨림·다리가 따로 노는 느낌 | 배터리 부족(충전 — 실제 사례), 서보가 뜨거우면 5분 쉬기, 바닥이 미끄러운지. 점검 예제 00의 몸통 불빛으로 배터리 확인 |
| 마이크로비트를 빼고 켜면 눈만 깜빡이고 버튼에 반응 없음 | 정상(대기 상태). 마이크로비트가 두뇌라 꽂아야 움직임 |
| 마이크로비트 없이 켜도 앞다리 두 개의 각도가 서로 다름 | 다리 영점(기준 각도)이 틀어진 것. 다리 나사 풀림 확인, 영점 보정은 코코아팹에 문의. 보정 전에는 물구나무·걷기 자제 |
| 로보독에 꽂으니 A·B 버튼을 누를 수 없음 | 정상(가려짐). 본체 버튼 사용 |
| LED는 켜지는데 PC에 MICROBIT 드라이브가 안 보임 | 충전 전용 케이블일 가능성이 큼. 데이터용 케이블로 바꾸기(실제 사례) |
| 로보독 전원은 켜지는데 동작이 이상함 | 로보독 마이크로비트를 다시 꽂고 전원 껐다 켜기, 점검 예제 00을 내려받아 통신·버튼·자세를 한 단계씩 확인 |
| 시뮬레이터 블록 편집기가 안 열림 | 학교망의 `makecode.microbit.org` 차단 → 글자 코드 탭(60초 뒤 자동) |

## 5. 개인정보·윤리

- 기본 수업(예제 01~04, AI 브리지)은 **얼굴 학습을 쓰지 않습니다.** 카메라는 책상·카드 쪽으로 향하게 하세요. 무선 예제 08(얼굴 추적)도 얼굴 대신 사진·그림 카드를 권합니다.
- AI 브리지의 영상은 브라우저 안에서만 처리되고 서버로 보내지 않습니다. AI 모델 파일만 내려받습니다.
- **로보독 도우미(AI 모드)에 쓴 글은 외부 AI 서버(Anthropic)로 전송됩니다.** 이름·학교·연락처를 쓰지 않도록 지도하고, 가정통신문·학교 정책에 함께 안내하세요. 규칙 도우미 모드는 전송하지 않습니다.
- 교사가 AI 도우미를 켰다면 Netlify에 `ASSISTANT_CLASS_CODE`(수업 코드)를 꼭 넣으세요. **넣지 않으면 주소를 아는 누구나 선생님 계정 요금으로 요청할 수 있습니다.**
- 학습 데이터 저장(.json)에는 사진이 아니라 숫자 특징만 들어갑니다. 그래도 수업 후 지우는 습관을 들이세요.
- 웹캠 사용은 학교 정책·가정통신문 안내를 따르세요.
