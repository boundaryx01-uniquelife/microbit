# 제조사 교안 분석과 우리 슬라이드 비교

작성: 2026-11-12 (KST)
분석 대상: 바운더리엑스 공개 저장소 `boundary-x/bitlearn-courseware` — 「AI 비트런 연구소 탈출 작전」 1~8화(웹 교안). 화면은 직접 열어 확인했고(1화 14장면), 구성은 차시 데이터(`lesson-bitrunNN/js/lesson.js`)를 글자로 읽어 셌다.
한계: 포니봇용 제조사 교안은 공개 저장소에서 찾지 못했다(비트런용만 있음). 홈페이지(boundaryx.io)는 이 작업 환경에서 열리지 않았다. 사용자가 말한 "제조사 슬라이드"가 다른 자료(PPT 등)라면 파일을 받아 다시 비교해야 한다.

## 1. 제조사 교안은 '슬라이드'가 아니라 학생이 직접 푸는 수업이다

| 요소 | 제조사 교안(확인한 사실) | 우리 포니봇 4차시 |
|---|---|---|
| 누가 넘기나 | **학생**이 이름을 넣고 자기 속도로 진행. 진행 기록이 기기에 남아 이어 하기. 교사는 투사 모드·수업 안내 | **교사**가 화면에 띄워 넘김. 학생은 보기만 함(함께 보기 기능은 화면 따라가기뿐) |
| 이야기 | 8화를 관통하는 이야기(연구소 문이 잠김 → 탈출). 이야기 장면 28쪽, 등장인물 4명 + 관리 AI. 그림 컷 위에 말풍선 | 이야기 없음. "문제 → AI → 전달 → 움직임" 설명 순서 |
| 한 쪽의 구성 | 설명 + **직접 눌러 보는 장치** + 더 자세히(접기) | 제목 + 아이콘 + 글 3줄 |
| 눌러 보는 장치 | 탈출 자물쇠 9, 딜레마 7, 경로 코딩 4, 조립 4, 분류 게임 3, 입력→처리→출력 3, 투표·카드·슬롯 등 | 없음 |
| 코딩 실습(8쪽) | 미션마다 **목표 → 예상 고르기 → 코딩 → 자동 확인(코드 글자를 규칙으로 검사) → 3단계 도움말 → 배운 점**, 도전 과제 | "이 블록을 쌓아요" 3단계 글. 확인은 교사 눈 |
| 틀렸을 때 | 보기별로 다른 설명, 도움말 3단계(점점 구체적으로) | 없음 |
| 동기 | 열쇠 조각, 탐험대 수첩, 역할 차례(질문·기록·행동·조립), 결과 카드, 복습 게임 | 활동지(종이)·모둠 발표 |
| 윤리 | 화마다 AI 윤리 질문 하나(예: "주사위로 정해도 될까?") | 4교시에 "확신 %는 맞을 확률이 아니다" 1회 |
| 교사 | 수업 안내, 정답은 교사 비밀번호로 잠금 | 장마다 교사 대본(발문·예상 답·진행·주의)·시간 합계 40분 |
| 그림 | 차시마다 전용 그림 10장 안팎, 캐릭터 일관 | 공용 아이콘, 포니봇 그림은 메인 카드 1장 |

요약: 제조사 교안의 품질은 그림이 아니라 **구조**에서 나온다 — 이야기로 이유를 주고, 학생이 예상하고, 직접 해 보고, 바로 확인받고, 막히면 단계별로 도움을 받는다. 우리 슬라이드는 이 고리가 통째로 없다.

## 2. 우리 쪽이 가진 것(제조사 교안에 없는 것)

- **실제로 움직이는 시뮬레이터**: 메카넘 이동·거리·라인·컬러 센서·OLED·LED를 브라우저에서 재현(시험 78항목). 제조사 교안의 코딩 확인은 코드 글자 검사라서 "블록은 맞는데 로봇은 벽에 부딪히는" 경우를 못 본다.
- **웹캠으로 가르치는 AI + 라디오 전달**(AI 브리지): 학생이 만든 AI가 같은 컴퓨터의 시뮬레이터 로봇과 실물 로봇을 움직인다. 제조사 교안은 AI를 이야기와 토의로 다룬다.
- **규칙 vs 학습 비교를 실제 데이터로**: 혼동 행렬, 확신 %, 처음 보는 카드 실험.
- **안전 설계**: 2초 신호 감시, 멈춤 잠금, 거리센서 500 = 못 읽음 처리.
- 교사 대본과 시간 계획.

## 3. 더 가치 있게 만드는 방향

제조사 구조(이야기 → 예상 → 실행 → 확인 → 도움 → 정리)를 받아들이되, 확인을 **코드가 아니라 로봇의 행동**으로 한다.

1. **미션 장**: 슬라이드 안에 시뮬레이터를 넣고, 목표를 로봇 행동으로 판정한다. 예) "상자 20cm 앞에서 멈췄나요?" → 시뮬레이터가 실제 거리로 확인. 예상 고르기 → 실행 → 예상과 비교.
2. **AI 미션**: AI 브리지 결과가 시뮬레이터 로봇에 전달되는 것을 이용해 "초록 카드를 보여 주면 출발, 빨강이면 2초 안에 멈춤"을 행동으로 판정.
3. **이야기**: 포니봇 4차시를 관통하는 이야기 하나(제조사 활동 그림 6종과 포니봇 그림을 장면으로 사용, 말풍선은 글로 얹음).
4. **보기별 설명·3단계 도움말·복습 게임**: 틀린 이유를 바로 알려 준다.
5. **학생 진행 기록**: 이름으로 시작, 미션 통과 기록, 결과 카드. 교사 화면은 지금의 대본을 유지.
6. 실물 미검증은 그대로 표시한다 — 시뮬레이터 통과가 실물 통과를 뜻하지 않는다는 점을 미션마다 "실물로 다시 확인" 단계로 둔다.

## 4. 주의

- 제조사 교안의 엔진·그림·문장을 그대로 가져오지 않는다(저장소에 라이선스 파일 없음). 구조만 참고하고 코드는 우리 뷰어에 새로 쓴다. 제조사 그림은 이미 허락받아 쓰는 `bridge/ponybot/assets/official/` 범위만.
- 비트런(걷는 로봇)과 포니봇(메카넘 바퀴)은 교구가 달라 내용은 옮길 수 없다.
- 행동 판정은 시뮬레이터(추정 모델) 기준이다.
