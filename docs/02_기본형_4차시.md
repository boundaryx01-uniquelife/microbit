# 4차시 기본형 — "규칙으로 움직이는 로봇 vs 배워서 움직이는 로봇"

- 대상: 초등 5~6학년
- 시간: 4차시(2+2 블록 권장)
- 목표
  1. 순차·조건 구조로 로보독을 움직이는 프로그램을 만든다.
  2. 사람이 정한 **규칙(센서+조건문)**과 데이터로 **학습한 AI**의 차이를 설명한다.
  3. AI 인식 결과를 이용해 생활 속 문제를 해결하는 로보독 동작을 설계·구현한다.
- 준비물·교사 사전 작업: `01_소개형_2차시.md`와 동일 + 그림 카드(음식·물건 등) 모둠당 3~4장

## 차시 개요

| 차시 | 주제 | 핵심 개념 | 예제 |
|---|---|---|---|
| 1 | 로보독과 첫 만남 | 피지컬 AI, 순차 구조 | `01_hello-robodog` |
| 2 | 규칙으로 반응하기 | 센서, 조건문(만약~라면), 반복 | `02_distance-rule` |
| 3 | 배워서 반응하기 | 데이터·학습·확신도, 라디오 통신 | `00_bridge-receiver`, `03_ai-traffic-dog` |
| 4 | 우리 모둠 AI 로보독 | 문제 정의·설계·구현·공유, AI 윤리 | `04_ai-team-template` |

## 1차시 — 로보독과 첫 만남 (40분)

- 도입(5): 로보독 시연, "피지컬 AI" 낱말 소개
- 전개(30)
  - 부품 관찰(8): 눈·몸통 LED, 거리센서, 카메라, 마이크로비트 자리
  - MakeCode 확장 추가 실습(7): `kocoafab/robodog` **전체 입력**해야 검색됨
  - 순차 코딩(15): 표정 → 소리 → 인사 자세 → 준비 자세. **마지막에 '준비' 자세** 넣기(기초 교안 주의사항)
- 정리(5): 내 로보독의 "인사 장면" 짝에게 보여 주기

## 2차시 — 규칙으로 반응하기 (40분)

- 도입(5): "로봇이 벽에 부딪히지 않으려면 무엇이 필요할까?"
- 전개(30)
  - 센서값 관찰(8): A 버튼으로 거리센서 값을 마이크로비트에 표시 → 손을 가까이/멀리
  - 기준값 정하기(7): 모둠이 "가까움"의 기준을 정함
  - 조건문 코딩(15): `02_distance-rule` — 가까우면 멈춤+빨강+"비켜", 멀면 천천히 전진
- 정리(5): **"이 로봇은 사람이 정한 규칙대로만 움직인다."**
  → 질문: "빨간 신호등을 보고 멈추게 하려면 규칙을 어떻게 쓰지?" (규칙으로는 어렵다는 것 체감)

## 3차시 — 배워서 반응하기 (40분)

- 도입(5): 2차시 질문 이어가기. "색을 규칙으로 설명하기 어렵다면, **보여 주며 가르치자!**"
- 전개(30)
  - AI 학습(10): AI 브리지에서 빨강·노랑·초록·배경 카드 학습(각 30장 이상)
  - 연결 이해(5): 웹캠 → AI → 다리 마이크로비트 → 라디오 → 로보독 (칠판 그림)
  - 코딩(15): `03_ai-traffic-dog`의 `신호에반응하기` 함수에서 각 신호의 행동을 모둠이 바꾸어 봄
- 정리(5): 규칙 vs 학습 비교표 작성

| | 규칙 로봇(2차시) | AI 로봇(3차시) |
|---|---|---|
| 누가 기준을 정했나? | 사람(기준값 20) | 데이터(사진) |
| 잘하는 일 | | |
| 틀리는 경우 | | |

## 4차시 — 우리 모둠 AI 로보독 (40분)

- 도입(5): 문제 카드 고르기 — 급식 알레르기, 교실 정리, 친구 맞이, 위험 알림 중 1개
- 전개(30)
  - 설계(8): "AI가 무엇을 보면(카드 1~3) → 로보독이 무엇을 하나" 표 작성
  - 학습·구현(17): AI 브리지에 모둠 카드 학습 → `04_ai-team-template`의 TODO 채우기
  - 윤리 점검(5): ① 사람 얼굴을 찍지 않았나? ② AI가 틀리면 누가 확인하나? ③ 모두에게 공평한가?
- 정리(5): 모둠 시연 + 칭찬 한마디
